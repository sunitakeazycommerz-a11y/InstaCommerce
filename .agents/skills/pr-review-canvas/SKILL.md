# PR Review Canvas (Antigravity Artifact)

Build an interactive, structured Antigravity Artifact that presents a PR diff reorganized for reviewer comprehension — not in raw file-tree order.

## Artifact Target

Write the resulting review artifact directly to the Antigravity Artifact directory:
`<appDataDir>/brain/<conversation-id>/pr-review-<pr_number_or_slug>.md`
Always provide `ArtifactMetadata` with `UserFacing: true`, a concise `Summary`, and `RequestFeedback: false`.

## Gather the diff

Collect the diff via `run_command`:
```bash
gh pr diff <pr> # or git diff origin/main...HEAD
```
If no PR link or branch is provided, ask the user which diff/PR they wish to review before proceeding.

## Group changes for reviewer comprehension

Reorganize into sections ordered by reviewer value:

1. **Executive Summary & Risk Assessment**:
   - High-level intent, affected subsystems, and rollout blast radius.
   - Use GitHub alerts: `> [!WARNING]`, `> [!IMPORTANT]`, or `> [!NOTE]`.
2. **Architecture & State Transitions**:
   - Visualize behavioral changes using Mermaid diagrams (`sequenceDiagram` or `flowchart TD`).
3. **Core Logic**:
   - New behaviors, algorithms, state machines, API surface changes.
   - Show code snippets with file links: `[Filename](file:///path/to/file#L10-L40)`.
   - Distill intricate logic into concise pseudocode or execution traces.
4. **Wiring & Integration**:
   - Routing, DI bindings, config plumbing that connects the core logic.
5. **Boilerplate & Mechanical**:
   - Imports, formatting, renames, autogenerated code. Summarize cleanly with stats.

## Verification Checklist

Provide a concrete verification matrix specifying:
- Targeted test commands (`./gradlew :services:...`, `go test`, `pytest`).
- Falsifiable evidence proving the change functions as intended.
